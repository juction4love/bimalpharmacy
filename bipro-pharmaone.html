What is BIPRO PharmaOne?

BIPRO PharmaOne is a single-PC, offline retail pharmacy management application. It stores all data in a local PostgreSQL database — no cloud account, no internet subscription, no third-party server receives your pharmacy or patient data during normal operation.

  • Sales: Cash sales and credit sales with customer ledger, cash memo history, and sales returns. Documents are printed as A4 or thermal challan.
  • Purchases: Cash and credit purchases, purchase returns, and supplier claim register.
  • Inventory: Batch tracking (FEFO), stock & expiry control, stock adjustments, physical counts, inventory valuation, and carrying-cost revaluation.
  • Prescription Register: Immutable prescription records with product linkage (v1.0.6).
  • Controlled Drug Register: Dispensing records for Nepal DDA schedule A–D controlled substances, immutable after save (v1.0.6).
  • Accounting: Double-entry general ledger, trial balance, profit & loss, balance sheet, and day/cash/bank books.
  • Finance: Customer receipts, supplier payments, expense records, other income, and fund transfers.
  • Reports: Purchase book, sales book, VAT register, party statements, outstanding dues, and inventory valuation.
  • Backup: Daily automatic backup (last 30 kept) and manual backup on demand. Backup files are saved to your local computer — no automatic cloud upload.

Regulatory note: Sales documents are labelled CHALLAN (चालान). BIPRO PharmaOne is not IRD-approved, CBMS-certified, DDA-approved, or an authorised VAT invoice system. Live CBMS transmission is not enabled in this release. It is a local record-keeping tool for retail pharmacy operations.

Installation instructions

  1. Download BIPRO_PharmaOne_Setup.exe using the button above.
  2. Verify the SHA-256 checksum (see below) if you want to confirm the file is unmodified.
  3. Run the installer. Accept the User Account Control (UAC) prompt if asked — PostgreSQL requires administrator rights to install as a Windows service.
  4. Follow the setup wizard. PostgreSQL 17 and the .NET 10 Runtime are installed automatically if not already present.
  5. When setup finishes, launch BIPRO PharmaOne from the Start menu or desktop shortcut.
  6. On first run, the setup wizard asks for your business name, address, phone number, and optional PAN/VAT and drug licence numbers. It also creates an Administrator account (username and password) for the application.
  7. Set your fiscal year and starting cash memo number as instructed by the wizard.

Never uninstall and reinstall to reset data. Reinstalling does not erase the database. Take a manual backup from Settings → Database Backup before any major change, and store copies on a USB drive or external disk.

Your data stays on your computer

BIPRO PharmaOne stores all pharmacy data — sales, purchases, customers, products, accounting journals — in a local PostgreSQL database on your PC. No data is sent to any remote server during normal operation. The application works fully offline after installation and does not require a cloud login to function.

Backup files are saved to a folder on your local computer (%LOCALAPPDATA%\BIPRO PharmaOne\Backups by default). The application does not upload backups to any cloud service automatically. Copy backup files to a USB drive or external disk regularly — if your PC fails, backups stored only on the same machine may be lost.

The Nepal IRD / CBMS Readiness page is included in Settings for future configuration. Live CBMS transmission is not enabled in this release.

Activation Key

BIPRO PharmaOne v1.0.6 requires an Activation Key issued by the software developer. The key is verified offline using RSA-2048 device binding — no internet connection is needed for activation or day-to-day use.

To activate: open Settings → Business Profile and use the activation panel. Paste the key provided by the developer. A key is tied to this installation and cannot be transferred to a different machine without a new key.

If you need an Activation Key, contact the developer who installed the software.

Release notes — v1.0.6 (2026-11-07)

  • Activation Key licensing: RSA-2048 offline license with device binding. The application requires a valid Activation Key; activation and all subsequent use are fully offline.
  • Controlled Drug Register (CDR): Records controlled substance dispensing per Nepal DDA schedule A–D. Each CDR entry is immutable after save.
  • Prescription Register: Immutable prescription records with product linkage.
  • Inventory carrying-cost revaluation: When a purchase rate changes after a goods receipt is posted, the difference in carrying cost is now correctly journalised, keeping COGS accurate. Applied retroactively on first upgrade.
  • .NET 10 LTS: Runtime upgraded from .NET 8 to .NET 10 LTS (self-contained, no separate .NET install required).
  • PostgreSQL 17.11-5: Updated EDB bundled PostgreSQL installer.
  • Security improvements: Database trigger privileges tightened; balance sheet Current Earnings sign corrected.

Release notes — v1.0.3 (2026-10-28)

  • 55 database migrations applied; full clean-install acceptance test passed.
  • Canonical party master: a customer and supplier with the same PAN/VAT number are now unified under a single party record.
  • COGS and accounting restoration: cost-of-goods-sold and journal posting functions fully restored.
  • Application Administrator authentication: first-run wizard now creates an Administrator login.
  • Administrator password reset requires maintenance-access credential (migration 0055).
  • Startup deadlock fix: database upgrade progress window no longer causes "Not Responding".

Known limitations

  • Single-PC local setup only. There is no built-in multi-user networking or remote access in the current version.
  • Sales documents are labelled CHALLAN, not VAT invoice. This application is not a substitute for a government-approved billing system.
  • Printer compatibility is tested with common laser and thermal printers but not verified across all printer models.
  • Nepali BS date entry is supported for expiry fields. Full BS-calendar input for all date fields may be added in a future version.
